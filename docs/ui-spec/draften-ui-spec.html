Frontend UI Specification

Draften

by Ankur Sinha · MIT © 2026 Ankur Sinha · sinhaankur.com

One canvas for vector design, structured diagramming, decks and documents — free and open source. A design-system spine, real component code, tech-stack plugins, GitHub sync with branches and PRs, and a runner that opens your repo's product in a preview window, no localhost ritual. Light is the default theme, dark one flip away; deep violet is the one brand color.

Light + Dark React + plain CSS Inter No paywall UI
Desktop ≥ 1440, keyboard-first. Mockups are reference renderings; the token block in 05 is copy-paste CSS.
00 · Brand

The route-D

The mark is the letter D drawn the way the product draws: its bowl is an auto-routed connector with rounded elbows, and a vector anchor diamond sits on the path like a selected point — drafting and diagramming in one letterform, authored by Ankur Sinha. It reduces to a plain stroked D at 16 px, sets in one color per ground, and needs no gradient.

draften.
draften.
Wordmark. Lowercase Inter 700, −3.5% tracking, accent full stop — plain, confident, open-source friendly. Never letterspaced, never outlined.
Draften Violet #7048E8. The one brand color — deep violet, deliberately not another blue tool (light theme deepens it to #5B34D6). Everything else is ink and paper; the board-kind spectrum is functional color, not brand.
Motif. The dot grid and the handle-line. Marketing and empty states reuse canvas furniture — ports, elbows, anchors — never abstract swooshes.
Voice. Plain and generous: "Free forever. MIT." Buttons say what happens ("Commit & push"), never marketing verbs. No nags, no locks, no trials.
01 · Layout

Three panes, one canvas, no modes

1 — One surface, one tool row. Design tools (frame, rect, ellipse, text) and diagram tools (shape, connector, sticky) share a single row. A board's kind seeds defaults — grid, starter objects — but never restricts tools: a journey map accepts frames; a wireframe accepts connectors.
2 — Left rail: Boards over Layers. Boards are a nestable tree (canvas management) mirrored by the top-bar breadcrumb; drag a row onto another to nest. Layers scope to the active board — frames, groups, shapes, connectors and stickies are peers; ⌘G groups, Tidy auto-arranges.
3 — Right rail: four tabs. System (the design-system spine: brand kit → tokens → atoms → … → pages, versioned), Inspect (context properties + per-object notes), Stack (connections & plugins), ✦ Assistant. Selection badges Inspect; nothing auto-switches. The spine edits in place: a brand-kit swatch opens a token popover (contrast-checked, where-used), an atom or molecule opens as a master board — publishing is a versioned draft, never a silent swap.
4 — Code is a projection. Design · Split · Code, top right. Split docks a live editor beside the canvas; Code fills the stage with the board's components as files. Selection ↔ caret stay in sync both ways (moment C).
5 — Diagram chrome is contextual. Ports fade in on hover, connectors auto-route with rounded elbows, reroute handles appear only on selection. Nothing persists on canvas that isn't content.
6 — Stack is a panel, not a settings page. Git hosts (GitHub, GitLab, Bitbucket, self-hosted), PostgreSQL, REST APIs, a terminal session and the import pipeline (.fig, .sketch, .graffle, .xd, .drawio, .pdf…) are one plugin registry (moment D). A connected database lets Inspect bind layers to live columns.
7 — Sync is a chip. Branch + ahead/behind live in the top bar. One commit carries board JSON and component code together, to a private or public repo (moment E) — design and code never drift apart in history. Sharing that repo is multiuser: boards merge at object level, so parallel edits combine; a same-property collision opens a visual picker — raw git conflicts never surface.
8 — Notes travel with the work. Stickies are canvas objects; every object also takes an Inspect note, surfaced as a quiet ⓘ dot — review happens on the canvas, not in a side tool.
9 — Open source is ambient. MIT badge and GitHub link in the status bar, version tag by the wordmark. No locked features, so no billing chrome exists anywhere.
Default · LightFirst-run theme — friendly in daylight, print-true; every value is a token, remembered per user.

05 · Design tokens

Two themes, one contract

Light is :root; dark overrides under [data-theme="dark"] — components never branch on theme. Body text runs ≥ 12 px Inter; canvas chrome may drop to 10.5 px only for read-only meta.

06 · Gap analysis

Closing the efficiency gap

What each benchmark actually contributes: VS Code — keyboard command surface, real language tooling, an extension economy. Sketch — vector craft, math-everywhere inputs, native speed. Figma — collaboration, auto layout, effortless sharing. Draften's edge is that code is already the source of truth — every gap below should be closed through that, not beside it.

PrioGapBenchmarkHow Draften closes it
P0Command paletteVS Code ⌘⇧P / Figma ⌘/⌘K searches every command, tool, board, component and token from one field; fuzzy match, recent-first, executes without the pointer. The single biggest speed multiplier.
P0Real language service in Code viewVS CodeTypeScript language server in a worker: autocomplete, hover types, inline diagnostics, rename-across-board, format-on-save. Syntax highlighting alone is not "VS Code-grade."
P0Canvas performance budgetFigma / Sketch nativeGPU renderer (WebGL/WebGPU), 60 fps pan-zoom at 5k objects, < 50 ms interaction budget, virtualized Boards/Layers lists, connector auto-routing in a worker, < 1.5 s cold open restoring exact viewport.
P0Auto layout that is flexboxFigma Auto LayoutStack, wrap, gap and constraints that serialize 1:1 to the component's flex/grid code. No translation layer to drift — Draften's structural advantage over Figma's dev-mode export.

07 · Experience framework

Governed by the Universal Experience Framework 1.0

Every screen in this spec is designed and reviewed against Ankur Sinha's Universal Experience Framework — laws of UX & cognition, Nielsen's ten heuristics, WCAG 2.2 AA and an applied per-screen method (sinhaankur.com/framework). When spec and principle conflict, the principle wins and the spec gets fixed. In-app it is ✦ Assistant's critique rubric: "Critique this board" scores the active screen against the ten heuristics with severities.

1 One primary action per screen
The active tool is the shell's only solid accent; every dialog ends in exactly one filled button (Von Restorff).
2 Signal over surface area
The canvas is the hero; chrome recedes to two quiet grays, a 26 px status bar and contextual diagram chrome.
3 Answers you can act on
Import warnings carry "show on canvas"; sync states name the next step; errors state the fix. No dead-end data.
4 One system, not six
One token contract (05) drives both themes, the DS spine and the exported code — nothing branches by hand.
5 Progressive disclosure
Ports on hover, collapsed sections, notes behind ⓘ, "10 more…" folds — density is a choice, not a default.
6 Prevent, then forgive
Visual merge picker instead of git conflicts; undo toasts over blocking confirms; offline queues instead of failures.
7 Accessible by default
WCAG 2.2 AA floor: the contrast pairs in 05, full-height hit areas, the accent :focus-visible ring, never meaning by color alone.
✓ The applied method
Frame it · one primary action · pick the pattern · lay it out · design the states · write the words · accessibility pass · critique it. The pre-ship checklist ships as a ✦ command.
LawMnemonicWired into the shell
Hick's Law"More choices = more time."One tool row of eight, no mode to pick first; ⌘K collapses everything else into one searchable field with a default.
Fitts's Law"Big and close = fast."Controls pin to pane edges; 32 px buttons with full-row hit areas; ports give a 16 px hit area on a 7 px dot.
Doherty / response times"Answer under 400 ms or they drift."Motion caps at 240 ms; < 50 ms interaction budget (06); skeletons under 1 s; longer work backgrounds to the status bar.
Jakob's Law"Yours should work like the rest."Familiar pane grammar; keymap presets for Figma, Sketch and VS Code so muscle memory transfers (06).
Miller / chunking"Hold about seven — so chunk it."Panels chunk into labelled sections of 3–7 rows; tokens group by role; boards nest instead of sprawling.
Zeigarnik / goal-gradient"Unfinished things nag at you."The sync chip counts unpushed commits; import shows per-page fidelity; proposals stay dashed until accepted.
Peak–End rule"They remember the peak and the end."The peak: ghost proposals snapping solid on Accept (200 ms). The end: "Pushed ✓" and a quiet changelog entry.
Postel's Law"Accept messy in; give clean out."Every numeric field takes math and messy formats (06) and normalises to tokens on blur.

08 · Added in review

What was still missing

Raised in review and now specified. A guided design-thinking template (empathize → define → ideate → prototype → test) also ships, stringing journey, mind-map, flow and design boards into one project.

Opens design files, period
.fig (file or API token), .sketch, .graffle, .xd, .drawio, .vsdx, .svg, .pdf, images — one importer pipeline; every import gets the fidelity report (B).
Decks & documents are boards
Deck and doc board kinds use the same canvas tools; export editable .pptx, .docx, .md and clickable .pdf (F). Slides and pages, no second app.
Run & test, no localhost
Stack reads the repo, detects the framework, runs it in an embedded runtime; the live product opens in a preview window — resize, detach, test beside the design.
Branches & PRs
The sync chip switches branches; the commit sheet opens PRs; review renders as a visual board diff, never raw JSON (E).
Design systems, plural
Attach several, set a project default, start from bundled open systems (Draften Base, Material 3, Radix). Switching re-themes instances through tokens.
Intuitive by explanation
Rich hover help on every control — name, shortcut, one line of what it does, ⌥ for an example. Empty states teach the next action; ⌘K answers "how do I…".
Micro-interactions, one grammar
120 ms hovers and port fades · 200 ms ghost→solid accepts · 240 ms panel docks. One curve, no bounce; prefers-reduced-motion honored everywhere.
Updates like an app, on any device
Stable/beta channels, in-app release notes, plugins update independently. Browser or installed desktop; the repo carries work across devices.
Design lint & redlines
Token-drift and detached-style warnings; WCAG contrast and target-size checks inline; ⌥ measure overlays and a spec handoff view.
Groups & auto-arrange
⌘G groups (transparent to connector routing, double-click to enter). Tidy snaps a selection to a grid; tree and layered auto-layout re-flow whole diagrams; Layers can mirror canvas order.
Canvas management, deeper
Duplicate, archive and template boards; sections within a board; a minimap toggle for big canvases; ⇧1 fit, ⇧2 zoom to selection.
Extensions, VS Code-style
One API adds tools, panels, importers, exporters, themes and ⌘K commands. Browse and install from the in-app gallery without a restart; the marketplace is open.
Insights: heatmaps on the live product
Once shipped, an opt-in, self-hosted Insights plugin overlays real usage on the boards that designed it: click/tap heatmaps and scroll depth per page, rage-click and dead-click flags, funnel drop-off along the flow connectors, and lightweight "how did this feel?" micro-surveys for perception. Data stays in your own store (privacy-first, no third-party trackers); a heat layer toggles on any frame like the grid does.
Design ↔ evidence loop
Heat and survey data pin to the exact frame version that was live, so a redesign can be judged against its predecessor; a cold primary button or a missed hotspot becomes a note on the layer that owns it. The framework's rule stands: telemetry guides, real user research decides.
